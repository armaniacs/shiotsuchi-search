## Phase 1 — 修正：既存の設計問題を潰す

### Fix-1: mtime + size 二段階スキャン（⑥ → #17）

**現状の問題**  
インクリメンタル判定で全ファイルの SHA-256 を毎回計算している。数万ファイル規模では
ディスク I/O と CPU が壮大な無駄遣いになる。

**方針**  
- `notes_meta` テーブルに `file_size INTEGER` と `mtime INTEGER` カラムを追加
- スキャン時はまず size+mtime を比較し、一致すれば SHA-256 計算をスキップ
- 変化したファイルのみ SHA-256 再計算 → 変化があればトークナイズ・インデックス更新
- `notes_meta` スキーマのマイグレーション処理を追加

**影響範囲**  
- `core/src/db.rs` — スキーマ・クエリ変更
- `core/src/indexer.rs` — スキャンロジック変更

---

### Fix-2: Semantic 検索を Cargo feature flag でオプション化（③）

**現状の問題**  
`ort`（ONNX Runtime）が常に静的リンクされ、バイナリが数十 MB になる。
FTS5 キーワード検索だけ欲しいユーザーには Bloatware。

**方針**  
- Cargo feature `semantic` を定義（デフォルト: enabled）
- `ort` 依存・埋め込みモデル・ベクトル検索コードを `#[cfg(feature = "semantic")]` で条件コンパイル
- `--no-default-features` でビルドするとキーワード検索のみの軽量バイナリが生成される
- README にビルドオプション説明を追記

**影響範囲**  
- `Cargo.toml`（workspace + 各クレート）
- `core/src/lib.rs`, `core/src/search.rs`, `core/src/tokenizer.rs`（ort 使用箇所）
- `cli/src/main.rs`, `mcp/src/handler.rs`（semantic 呼び出し箇所）

### Fix-3: マルチ Vault ネイティブ対応（⑤ → #21）

**現状の問題**  
複数 Vault の切り替えに環境変数の手動設定が必要。UX が悪い。

**方針**  
- `config.toml` に `[[vault]]` セクションを追加（id, notes_dir, db_path）
- デフォルト Vault 指定に対応（`default = "work"` 等）
- CLI に `--vault <id>` フラグを追加（`dive`, `chart`, `scan` コマンド）
- MCP ツールにも `vault` パラメータを追加し、単一サーバーで複数 Vault をルーティング
- 既存の単一 Vault 設定は後方互換を維持

**影響範囲**  
- `cli/src/config.rs` — 設定スキーマ変更
- `cli/src/main.rs` — フラグ追加
- `mcp/src/handler.rs` — vault ルーティング
- `ref/cli.md`, `ref/mcp.md` — ドキュメント更新

## Phase 2 — 新機能：Frontmatter フィルタリング

### Feat-1: Frontmatter・タグ・日付によるフィルタリング（#10）

**概要**  
YAML Frontmatter の `tags` や `date` を解析してインデックス化し、
検索時に絞り込み条件として使えるようにする。

**方針**  
- `notes_meta` に `tags TEXT` と `frontmatter_date TEXT` カラムを追加
- インデックス時に Frontmatter をパースして格納
- `dive` コマンドに `--tag <tag>` と `--since <date>` フラグを追加
- SQL クエリに WHERE 条件として組み込む
- タイトル・タグマッチ時のスコアブースト（FTS5 rank 調整）

**影響範囲**  
- `core/src/db.rs` — スキーマ・クエリ
- `core/src/indexer.rs` — Frontmatter パース
- `core/src/search.rs` — フィルタ条件
- `cli/src/main.rs` — フラグ追加
