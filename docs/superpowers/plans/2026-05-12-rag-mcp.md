> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Update the MCP server to expose the new RAG chunk schema via `search_local_notes`, `get_surrounding_context`, `index_status`, and `rebuild_index` tools, replacing the old `search_vault` / `read_full_note` / `vault_status` tools.

**Architecture:** `tools.rs` and `handler.rs` are rewritten for the new tool surface. `call_tool` keeps the existing `db_path: &Path` signature — each handler opens `NoteDatabase::open(db_path)` per request (lightweight under SQLite WAL). A tokio multi-thread runtime is added for future extensibility; the stdio loop remains synchronous. `rebuild_index` delegates to the CLI rather than running background indexing in the MCP process.

## Task 3: Rewrite `handler.rs` with new tool handlers

**Files:**
- Modify: `mcp/src/handler.rs`

**Key implementation notes (verified against current codebase):**

1. **No `SearchError` type** — `search()` returns `Result<Vec<ChunkSearchResult>, DbError>`. There is no `SearchError::EmbedderUnavailable`. When `embedder` is `None` and mode is `Hybrid` or `Vec`, `search()` automatically falls back to `Fts` (see `core/src/search.rs:23-27`). The `vec` mode guard is handled in the handler with an explicit early return before calling `search()`.

2. **`extract_snippet` takes 4 arguments** — signature is `extract_snippet(text: &str, query: &str, max_lines: usize, max_chars: usize)`. Use `extract_snippet(&r.content, query, 3, 800)`.

3. **`NoteDatabase::open_readonly` returns `Connection`, not `NoteDatabase`** — it cannot call `.stats()` or `.get_surrounding_chunks()`. Use `NoteDatabase::open(db_path)?` in each handler arm (write connection, but no write operations are ever called from MCP handlers).

4. **`call_tool` signature stays as-is** — `(name, args, notes_dir, db_path)` matching the current `main.rs` dispatch.

5. **`get_tokenizer()` returns `Err(TokenizerError::NoModel)` when no model is available** — the MCP server runs without a Vaporetto model in typical deployments. `get_tokenizer()?` in `search_local_notes` would propagate this as a tool error. Instead, match on the error and return a user-facing guidance message. Pattern:

   ```rust
   let tokenizer = match get_tokenizer() {
       Ok(t) => t,
       Err(_) => return Ok(json!({
           "content": [{"type": "text", "text": "Full-text search requires a tokenizer model. Run 'shiotsuchi setup' to configure one, or set SHIOTSUCHI_MODEL_PATH."}]
       })),
   };
   ```

6. **`chunk_markdown` does not exist** — the actual API is `shiotsuchi_core::chunker::split_into_chunks(markdown: &str, tokenizer: &JapaneseTokenizer, file_path: &str) -> Vec<Chunk>`. It requires a tokenizer. Test `setup_db` helpers must obtain a tokenizer first via `shiotsuchi_core::tokenizer::get_tokenizer()`, and skip the test if it returns `Err` (no model). Use the `require_tokenizer!` macro pattern already used throughout the codebase:

   ```rust
   fn setup_db(temp: &TempDir) -> Option<std::path::PathBuf> {
       use shiotsuchi_core::{db::NoteDatabase, chunker::split_into_chunks};
       let tok = shiotsuchi_core::tokenizer::get_tokenizer().ok()?;
       let db_path = temp.path().join("test.db");
       let db = NoteDatabase::open(&db_path).unwrap();
       let chunks = split_into_chunks(
           "# Title\n\nThis is a searchable note about Rust programming.",
           &tok,
           "note.md",
       );
       db.insert_chunks(&chunks).unwrap();
       Some(db_path)
   }
   ```

   Each test then starts with `let Some(db_path) = setup_db(&temp) else { return; };` to skip gracefully when no model is present.

```rust
use serde_json::{json, Value};
use shiotsuchi_core::{
    db::NoteDatabase,
    models::SearchMode,
    search::{extract_snippet, search},
    tokenizer::get_tokenizer,
};
use std::{path::Path};

fn format_results_markdown(results: &[shiotsuchi_core::models::ChunkSearchResult], query: &str) -> String {
    if results.is_empty() {
        return "No results found.".to_string();
    }

    let mut out = String::from("### RETRIEVED CONTEXT ###\n\n");
    for (i, r) in results.iter().enumerate() {
        let header = r.parent_header.as_deref().unwrap_or("(top level)");
        out.push_str(&format!(
            "## Source {}: {} > {}\n\n",
            i + 1,
            r.file_path,
            header
        ));
        // extract_snippet(text, query, max_lines, max_chars)
        let snippet = extract_snippet(&r.content, query, 3, 800);
        out.push_str(&snippet);
        out.push_str(&format!("\n\n_Chunk ID: {} | Score: {:.4}_\n\n---\n\n", r.chunk_id, r.score));
    }
    out.push_str("### END RETRIEVED CONTEXT ###\n");
    out
}

pub fn call_tool(
    name: &str,
    args: &Value,
    notes_dir: &Path,
    db_path: &Path,
) -> Result<Value, Box<dyn std::error::Error>> {
    match name {
        "search_local_notes" => {
            let query = args["query"].as_str().unwrap_or("").to_string();
            let limit = args["limit"].as_u64().unwrap_or(10).min(50) as usize;
            let mode_str = args["mode"].as_str().unwrap_or("hybrid");

            // MCP server runs without an embedder. Return a guidance message for vec-only mode.
            // hybrid and fts both work — search() auto-falls-back to Fts when embedder is None.
            if mode_str == "vec" {
                return Ok(json!({
                    "content": [{
                        "type": "text",
                        "text": "Vector search requires a model. Use mode='fts' or run 'shiotsuchi setup' to configure an embedder."
                    }]
                }));
            }

            let mode = if mode_str == "fts" { SearchMode::Fts } else { SearchMode::Hybrid };

            // Validate notes_dir is reachable (path traversal check)
            let _canonical_vault = notes_dir.canonicalize()?;

            let db = NoteDatabase::open(db_path)?;
            let tokenizer = match get_tokenizer() {
                Ok(t) => t,
                Err(_) => return Ok(json!({
                    "content": [{"type": "text", "text": "Full-text search requires a tokenizer model. Run 'shiotsuchi setup' to configure one, or set SHIOTSUCHI_MODEL_PATH."}]
                })),
            };
            let results = search(&db, &tokenizer, &query, limit, mode, None)?;

            let markdown = format_results_markdown(&results, &query);
            Ok(json!({
                "content": [{"type": "text", "text": markdown}]
            }))
        }

        "get_surrounding_context" => {
            let chunk_id = args["chunk_id"].as_i64()
                .ok_or("chunk_id must be an integer")?;
            let window = args["window"].as_u64().unwrap_or(2).min(5) as usize;

            let db = NoteDatabase::open(db_path)?;
            let chunks = db.get_surrounding_chunks(chunk_id, window)?;

            let mut out = format!("### Context around chunk {} ###\n\n", chunk_id);
            for c in &chunks {
                let marker = if c.id == Some(chunk_id) { "**[SELECTED]** " } else { "" };
                let header = c.parent_header.as_deref().unwrap_or("(top level)");
                out.push_str(&format!("## {}Source: {} > {}\n\n{}\n\n---\n\n",
                    marker, c.file_path, header, c.content));
            }

            Ok(json!({
                "content": [{"type": "text", "text": out}]
            }))
        }

        "index_status" => {
            let db = NoteDatabase::open(db_path)?;
            let stats = db.stats()?;
            let text = format!(
                "Indexed files: {}\nTotal chunks: {}\nVector-indexed chunks: {}\nDB size: {:.1} MB\n\
                 Note: this status may be slightly stale if background indexing is running.",
                stats.total_files,
                stats.total_chunks,
                stats.vec_indexed_chunks,
                stats.total_size_bytes as f64 / 1_048_576.0
            );
            Ok(json!({"content": [{"type": "text", "text": text}]}))
        }

        "rebuild_index" => {
            // MCP server is read-only by design. Delegate rebuild to the CLI.
            Ok(json!({
                "content": [{
                    "type": "text",
                    "text": "To rebuild the index, run: shiotsuchi chart --force\n\
                             The MCP server will automatically use the updated index."
                }]
            }))
        }

        _ => Err(format!("Unknown tool: {}", name).into()),
    }
}
```

### TDD 手順の修正

旧計画の Task 2/3 は「Step 1 でテスト追記 → Step 3 でファイル全体を置換」という構造だったため、Step 1 で追記したテストが Step 3 で上書きされる矛盾があった。修正版では「`#[cfg(test)]` ブロックのみを先に置き換えて失敗確認 → 実装部のみを置き換えてパス確認」の 2 段階に分離している。
