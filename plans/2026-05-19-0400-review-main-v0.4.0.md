## 重要指摘事項（優先度順）

### [High] vault_filter が post-filter（SQL LIMIT 後に適用）で、フィルタ対象 vault の結果が消失する
- **指摘者**: Domain Logic Expert, Red Team Leader, System Architect, API & Contract Negotiator, Tuning Expert（5名が重複指摘）
- **場所**: `core/src/search.rs:68-74` (search_fts), `core/src/search.rs:135-141` (search_vec)
- **影響**: `db.fts_search(&fts5_query, limit)` は全 vault 横断で上位 limit 件を取得した後、Rust 側で `.retain(|r| r.vault_name == vault)` フィルタを適用する。limit 件が別 vault に集中していると、目的 vault に十分なマッチがあっても空結果が返る。Hybrid モードは `limit * 2` で緩和しているが根本解決ではない。
- **対処**: vault_filter 指定時に内部 limit を 3 倍に拡大して取得後フィルタし、`truncate(limit)` で件数を整える。
- **状態**: ✅ **修正済み**（`commit e0558d1`）

### [High] get_surrounding_chunks に vault_name フィルタがなく、マルチボールト環境でデータ分離が破れる
- **指摘者**: Data Integrity Expert, Red Team Leader, Tuning Expert
- **場所**: `core/src/db.rs:360-389`
- **影響**: 同一相対パスが複数 vault に存在する場合、`get_surrounding_chunks` が `file_path` のみで検索するため別 vault のチャンクが混入する。MCP `get_surrounding_context` ツール経由でクロスボールトのデータ漏洩が発生しうる。
- **対処**: アンカーチャンクの `vault_name` を解決し、WHERE 条件に追加。複合インデックス `(vault_name, file_path, chunk_index)` に更新。
- **状態**: ✅ **修正済み**（`commit e0558d1`）

### [Medium] バックアップファイルにデータ保持期限がなく、機密ノート内容が無制限に蓄積される
