## 重要指摘事項（優先度順）

### [High] handle_search の total 取得が FTS クエリを再実行
- 指摘者: Tuning Expert
- 場所: `core/src/server/handlers.rs:169-176`
- 影響: FTS モードのたびに同一クエリを2回実行（1回目はページング用、2回目は total カウント用）。大規模ボルトで応答時間が実質2倍になる。
- 対処: `SELECT COUNT(*) FROM fts_chunks WHERE fts_chunks MATCH ?` 専用の軽量カウントクエリに切り替える。cursor ページング使用時は total 自体が不要なためスキップ可能。

### [High] MCP tool errors がログ出力なしに破棄
- 指摘者: SRE/Ops Specialist
- 場所: `mcp/src/main.rs:183`
- 影響: `handler::call_tool` がエラーを返した際、`Err(_)` で破棄され汎用メッセージのみ返される。本番環境でツール呼び出しが失敗した際、原因特定が不可能。
- 対処: `tracing::error!` で実際のエラー内容を記録する。
- 修正状況: **Test Experts により修正済み** ✅

### [High] ort-sys バイナリダウンロードの整合性検証が未適用の可能性
- 指摘者: Supply Chain Sentinel
- 場所: `core/Cargo.toml:38-42`
- 影響: Cargo.toml のコメントには ort-sys の SHA-256 検証バグ回避のため main ブランチから取得すると記載されているが、`[patch]` セクションも git override も存在しない。ビルド時にダウンロードされるバイナリの改ざん検証が機能していない可能性。
- 対処: ort-sys 2.0.0-rc.12 の crates.io リリースに修正が含まれているか確認し、コメントと実際の状態の乖離を解消する。

### [Medium] マイグレーションヘルパーの SQL インジェクション潜在リスク
- 指摘者: Blue Team, Data Integrity, Refactoring Evangelist, System Architect (4名重複)
- 場所: `core/src/migration/mod.rs:24,43-46`
- 影響: `format!()` でテーブル名・カラム名をSQLに補間。現在はハードコードされたリテラルのみだが、将来の misuse に脆弱。
- 対処: `validate_sql_ident()` で英数字+アンダースコアのみ許可するバリデーションを追加。
- 修正状況: **Test Experts により修正済み** ✅

### [Medium] `index_file_with_embedder` / `index_file` に経路探索防御が組み込まれていない
- 指摘者: Red Team Leader
- 場所: `core/src/indexer.rs:247-260, 446`
- 影響: 両関数は public で `IndexParams.file_path` をそのまま受け取る。現在の呼び出し元は検証済みだが、関数自体には防御がない。将来の呼び出し元が検証を省略すると vault 外のファイルがインデックスされる可能性。
- 対処: `pub(crate)` に縮小し、エントリポイントを限定する。または `debug_assert!` で防御を追加。

### [Medium] `spawn_rebuild` がユーザーの IndexConfig を無視してデフォルトで動作
- 指摘者: Domain Logic Expert
- 場所: `mcp/src/main.rs:232-235`
- 影響: MCP 経由の `rebuild_index` が `IndexConfig::default()` で構築されるため、CLI 設定の `exclude_dirs`・`include_extensions` 等が無視される。
- 対処: `spawn_rebuild` の引数に `IndexConfig` を追加し、`to_core_config()` → `IndexConfig::from_cli_configs()` 経由でユーザー設定を反映。

### [Medium] MCP サーバーの SensitiveDataConfig がハードコード
- 指摘者: Compliance & Privacy Guard
- 場所: `mcp/src/main.rs:318`
- 影響: `SensitiveDataConfig::default()` をハードコードで使用。ユーザーが config.toml でカスタムパターンを定義しても MCP 経由の出力には適用されない。
- 対処: `to_core_config()` 経由で `SensitiveDataConfig` を生成する。

### [Medium] 新規公開API関数のエラー型が `String` / `&'static str`
- 指摘者: API & Contract Negotiator, Legacy Bridge Architect
- 場所: `core/src/indexer.rs:208-242`, `core/src/models.rs:57-68`
- 影響: `resolve_vault_dir` / `resolve_file_in_vault` が `Result<PathBuf, String>` を返す。`SearchMode::FromStr` のエラー型が `&'static str`。呼び出し元がエラー種別をプログラム的に判別できない。
- 対処: 型付きエラー列挙型を定義する。

### [Medium] Health endpoint が依存関係の可用性を検証しない
- 指摘者: SRE/Ops Specialist
- 場所: `core/src/server/handlers.rs:80`
- 影響: `/api/v1/health` がDB接続状態やトークナイザー可用性を検証せず常に `{"status": "ok"}` を返す。
- 対処: Readiness probe 用にDB接続確認を追加。

### [Medium] 検索UIにページネーション controls が存在しない
- 指摘者: UI Expert
- 場所: `core/src/server/ui.html:455-494`
- 影響: API は cursor/offset ページネーションに対応しているが、ブラウザUI の検索結果には「Load more」ボタンがない。
- 対処: `next_cursor` を使った「Load more」ボタンを追加。

### [Medium] `constant_time_eq` のコメントが実装と矛盾
- 指摘者: Blue Team, Domain Logic Expert
- 場所: `core/src/server/handlers.rs:351-359`

- 対処: コメントを実装に合わせて修正。
- 修正状況: **Test Experts により修正済み** ✅
