CLIツールで `--help` を打出すたびに「コマンドが多すぎてどれを実行すればいいかわからない」と感じたことはありませんか。

[shiotsuchi-search](https://github.com/armaniacs/shiotsuchi-search) は日本語対応のMarkdownノート検索エンジンで、v0.4.14で `shiotsuchi` だけを実行したときのUXを大きく改善しました。サブコマンドを指定せずに起動すると、カテゴリ別に整理されたメニューと3ステップのオンボーディングウィザードが表示されます。

この記事では、CLIにTUI風の導線を追加した動機・設計・実装のポイントをまとめます。

## なぜウェルカム画面が必要だったか

shiotsuchiは開発を進めるうちにサブコマンドが15個に増えていました。`init`、`index`、`search`、`watch`、`doctor`、`tasks`...。既存ユーザーなら `shiotsuchi index` と `shiotsuchi search "query"` の流れを知っていますが、はじめて起動した人はどこから手をつけていいかわかりません。

`shiotsuchi --help` を打出せば一覧は見られますが、コマンド名だけでは「設定ファイルを作る」→「インデックスする」→「検索する」という導線がすぐには伝わりません。

そこで、サブコマンドなしで起動したときにウェルカム画面を表示し、ユーザーをステップバイステップで案内することにしました。

## どんな画面が出るのか

`shiotsuchi` だけを実行すると、こんなバナーが表示されます。

```
╔══════════════════════════════════════════════════╗
║            Shiotsuchi Search  v0.4.14           ║
║  データの潮流を導く — 日本語対応ノート検索エンジン  ║
║                                                  ║
║  🔰 はじめての方へ                                ║
║     この画面では以下の3ステップを                   ║
║     一緒に進められます                             ║
║     ① 設定ファイルを作る                           ║
║     ② ノートをインデックスする                      ║
║     ③ 検索してみる                                ║
╚══════════════════════════════════════════════════╝
```

その下にカテゴリ別メニューが並び、カーソルキーで選んでEnterを押すだけです。

```
実行する操作を選んでください (上下キー:移動, Enter:決定):

  🚀 オンボーディング  (init → index → search を一緒に完了)

  ── セットアップ ──
  init     設定ファイルを作成・編集する
  setup    埋め込みモデルをインストールする

  ── 検索・操作 ──
  search   ノートを検索する
  index    ノートをインデックスする

  ── 情報・メンテナンス ──
  stats    統計情報を表示する
  doctor   環境の状態を診断する

  ── 終了 ──
  exit     終了する
```

バナーの内容は環境に応じて変わります。設定ファイルがない場合は「はじめての方へ」、DBがまだない場合は「オンボーディングの続きから」、すべて揃っている場合は「クイックオンボーディング」と表示されます。

## 3ステップのオンボーディング

メニューの先頭にある「オンボーディング」を選択すると、init → index → searchを順番に実行してくれます。各ステップの前に「この内容で実行しますか？」と確認が入るので、途中で中断することもできます。

```
🔰 Step 1/3: 設定ファイルを作成します
  作成先: ~/.config/shiotsuchi/config.toml
  ノート: /Users/yaar/Notes
この内容で設定ファイルを作成しますか？ > Yes

✅ Step 1/3 完了: 設定ファイルを作成しました
Step 2 に進んでノートをインデックスしますか？ > Yes

⚡ Step 2/3: ノートをインデックスします
  ボールト: /Users/yaar/Notes
この内容でインデックスを実行しますか？ > Yes
... (インデックス実行中) ...
✅ Step 2/3 完了: ノートのインデックスが完了しました

🔍 Step 3/3: ノートを検索してみましょう
検索クエリを入力してください > プロジェクト計画
```

設定ファイルが既にある場合はStep 1をスキップし、DBが既にある場合は再インデックスの有無を確認します。ユーザーの状態に合わせて、必要なステップだけを実行する設計です。

## 設計上のポイント

### 状態検出でメッセージを分岐

ウェルカム画面の表示内容は、設定ファイルとDBの存在状態の組み合わせで決まります。

| 設定ファイル | DB | メッセージ |
|---|---|---|
| なし | なし | 🚀 オンボーディングを開始 |
| あり | なし | ⚡ オンボーディングを続ける |
| あり | あり | 🚀 クイックオンボーディング |

この3状態を `config_path.exists()` と `db_path.exists()` で判定し、メニューの先頭項目を動的に切り替えています。

### dialoguer で対話UIを構築

メニュー選択には [dialoguer](https://crates.io/crates/dialoguer) の `Select` を、確認プロンプトには `Confirm` を使い、検索クエリの入力には `Input` を使っています。すべて `dialoguer_theme()` でテーマを統一し、`NO_COLOR` 環境変数が設定されている場合はカラーテーマを無効化します。

```rust
// cli/src/util.rs
pub fn dialoguer_theme() -> Box<dyn dialoguer::theme::Theme> {
    if std::env::var("NO_COLOR").is_ok() {
        Box::new(dialoguer::theme::SimpleTheme)
    } else {
        Box::new(dialoguer::theme::ColorfulTheme::default())
    }
}
```

`NO_COLOR` は [no-color.org](https://no-color.org/) で策定された標準で、カラーサポートがないターミナルやCI環境での出力乱れを防ぎます。

### 非TTY環境へのフォールバック

パイプやCIで実行された場合は、対話メニューの代わりにコマンド一覧と `--help` の案内をテキストで出力します。

```rust
let is_tty = std::io::stdin().is_terminal() && std::io::stdout().is_terminal();

if !is_tty {
    println!("{}", messages::WELCOME_NON_TTY_COMMAND_LIST);
    return Ok(());
}
```

これにより、`shiotsuchi | less` やCIスクリプト内でもエラーにならず、静かにヘルプ情報を出力します。

### メッセージ定数の分離

ユーザーに表示する日本語メッセージはすべて `cli/src/messages.rs` の定数として集約しています。将来的なi18n対応や、メッセージの一括変更を容易にするためです。welcome.rs 内にハードコードされた文字列はありません。

### エラー時のリカバリ

オンボーディング中にエラーが発生しても、メニューに戻るだけで済みます。クラッシュしません。

```rust
if let Err(e) = run_onboarding(...) {
    eprintln!("⚠️ オンボーディング中にエラーが発生しました: {}", e);
}
// メニューを再表示して続行
```

## 実装にあたっての技術選択

### なぜratatuiではなくdialoguerか

TUIフレームワークとして[ratatui](https://ratatui.rs/)なども検討しましたが、shiotsuchiのウェルカム画面は「メニュー選択 → 確認 → 実行」という単純なフローです。ratatuiはフルスクリーンのUIに適していますが、今回のような「選んで実行するだけ」のユースケースにはdialoguerの `Select` / `Confirm` / `Input` で十分でした。

依存を減らし、ビルド時間を短縮する観点でもdialoguerが最適解でした。

### バナーの動的幅

バナーの内側幅は固定の50文字で統一していますが、完了画面はコンテンツに合わせて動的に計算します。

```rust
let inner_w = lines.iter().map(|l| l.len()).max().unwrap_or(46);
```

これにより、コンテンツが変わっても枠が崩れない表示になっています。

## 今後の展望

現時点ではウェルカム画面は `dialoguer` の文字ベースUIですが、将来的には以下のような拡張を検討しています。

- **ウィザードの進捗表示**: ステップごとの完了状況をインジケータで表示
- **検索結果のインタラクティブ表示**: 検索結果を選んでファイルを開く
- **設定の対話的編集**: `config.toml` の各フィールドを対話的に変更

ただし、shiotsuchiのコアは「高速検索」にあります。TUIはあくまで入口のUX改善であり、本質的な検索体験を損なわない範囲で機能を追加していく方針です。

## さいわいに

CLIツールにTUI導線を追加する場合、以下のポイントが押さえどころです。

1. **状態に応じた表示切り替え** — 設定ファイルやDBの有無でメッセージを分岐する
2. **非TTYへのフォールバック** — パイプやCIでも動作するようにする
3. **メッセージの分離** — i18nや一括変更に備えて定数化する
4. **エラー時のリカバリ** — クラッシュせずにメニューに戻る設計にする
5. **適切なツール選び** — フルTUIか軽量な対話UIかをユースケースに合わせて選ぶ

shiotsuchi-searchは `cargo install shiotsuchi` でインストールできます。設定ファイルを作成せずに `shiotsuchi` だけで起動すると、ウェルカム画面が表示されるので、ぜひ試してみてください。

```sh
cargo install shiotsuchi
shiotsuchi
```
