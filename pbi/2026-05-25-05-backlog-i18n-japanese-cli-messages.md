# PBI: CLI メッセージ・エラーの日本語 i18n 対応

## ユーザーストーリー
日本語特化ツールを使う日本語ユーザーとして、CLIのヘルプやエラーメッセージを日本語で読みたい、なぜなら英語のエラーコードをそのまま出すのは日本語特化ツールとして矛盾しているから

## ビジネス価値
- ターゲットユーザー層（日本語ノートユーザー）の UX を向上
- 設定エラーや DB エラー時の対処がしやすくなる

## BDD 受け入れシナリオ

```gherkin
Scenario: 設定ファイルパースエラーが日本語で表示される
  Given 不正な config.toml が存在する
  When ユーザーが `shiotsuchi dive "検索語"` を実行する
  Then "設定ファイルの読み込みに失敗しました: ..." という日本語エラーが表示される

Scenario: --help が日本語で表示される
  When ユーザーが `shiotsuchi --help` を実行する
  Then コマンドの説明が日本語で表示される
```

## 受け入れ基準
- [ ] 主要なエラーメッセージが日本語化される
- [ ] `--help` のコマンド説明が日本語になる
- [ ] 英語環境でも動作が壊れない（i18n 基盤を用意する）

---

## ⚠️ 実装者向け注記

### 着手前の調査

```bash
# エラーメッセージの発生箇所を洗い出す
grep -rn "eprintln!\|println!\|Error:\|error!" cli/src/ | head -40
grep -rn "thiserror\|#\[error" core/src/ | head -30
```

### 実装方針

完全な i18n フレームワーク（`fluent` 等）は重すぎる。  
まず `cli/src/messages.rs` を新規作成し、日本語メッセージ定数をまとめる簡易アプローチで始める：

```rust
pub const ERR_CONFIG_PARSE: &str = "設定ファイルの読み込みに失敗しました";
pub const ERR_DB_NOT_FOUND: &str = "データベースが見つかりません。`shiotsuchi chart` を先に実行してください";
```

`clap` のヘルプ文字列は各 `#[command(about = "...")]` を日本語に変更する。

### 落とし穴

- `thiserror` の `#[error("...")]` マクロで定義されたメッセージは `core/` にある。  
  ライブラリ（core）のエラーメッセージを日本語にするか、CLI レイヤーで変換するかを決めること。  
  **推奨**: core のエラーは英語のまま、CLI 出力時に日本語ラッパーメッセージを追加する。
- `RUST_LOG` での英語ログはそのままで良い（デバッグ用）。ユーザー向け出力のみ日本語化する。
